A desktop is a Debian Linux virtual machine with the XFCE graphical desktop. Each task has its own. The person on the desktop can use `sudo` without a password and can run Docker, and so can the agent.

## Apps

An environment chooses which apps get a button on the desktop's panel.

| App | What it is | On by default |
| --- | --- | --- |
| Chrome | The web browser (Chromium). The agent uses it where you can watch. | Yes |
| VS Code | The code editor. Files the agent changes open here. | Yes |
| Terminal | A command line. | Yes |
| Files | The file manager. | Yes |
| Writer | Documents (LibreOffice). | No |
| Calc | Spreadsheets (LibreOffice). | No |
| Impress | Slides (LibreOffice). | No |
| Android phone | An Android phone in its own window. | No |
| iPhone | An iPhone simulator in its own window. Needs a Large desktop. | No |

## Developer tools

These are installed on every desktop, whatever the environment:

- git, Git LFS and the GitHub CLI (`gh`)
- Node.js 22
- Python 3 with pip and venv
- The .NET 10 SDK
- Docker Engine with Compose and Buildx
- A C and C++ toolchain (`build-essential`)
- Java 17 and the Android SDK
- `sqlcmd`, for SQL Server in a container
- The system libraries Playwright's browsers need. The browsers themselves are the project's own version, installed with `npx playwright install`.

Anything else a project needs goes in the environment's [setup script](/docs/environments#setup-script).

## Phones

A desktop can have an Android phone and an iPhone on it, each in its own window beside the browser. Add `android` or `iphone` to the environment's apps. You can click and type on a phone as you do on the rest of the desktop, and the agent uses it the same way: it opens the app, reads the screen, taps through what it changed and says what it saw.

**Android.** The emulator runs on every size, and best on Standard or Large. The agent builds the Android app on the desktop, with the project's own tools.

**iPhone.** The simulator is Apple's own iOS, and it needs a Large desktop. It is already on the image these desktops start from, so nothing is installed when a task starts.

An iPhone app can only be built on a Mac, and a desktop is not one. So the desktop sends the app's source to Workstream, which builds it on a Mac and keeps the app for your team. Nothing is added to your repository.

- A new build takes fifteen to thirty minutes. It is needed only when the app's native code changed: a native package, a config plugin or native source.
- A change to JavaScript or Dart uses the app your team already has, and reaches the phone from the dev server on the desktop.
- Workstream builds Expo apps today. React Native, Flutter and plain Xcode projects take the same path and have not been tried on a real project yet.
- Siri does not work on the simulator, and neither does anything that needs a real device.

The minutes a Mac spends on your team's builds are on the [Usage page](/docs/usage-and-limits#iphone-builds).

## Sizes

An environment chooses the size of its desktops.

| Size | Processor | Memory | Disk |
| --- | --- | --- | --- |
| Small | 2 cores | 8 GB | 64 GB |
| Standard | 4 cores | 16 GB | 64 GB |
| Large | 8 cores | 32 GB | 128 GB |

A project that runs a database, an API and a web bundler at the same time wants Large.

## How long a start takes

A new desktop's screen is in your browser about half a minute after you start the task. Getting the machine is the slow part, between fifteen seconds and a minute. The screen appears a few seconds before the agent says anything, and while you wait the task shows which step it is on: getting a computer, turning it on, starting the agent.

After that the agent prepares the desktop where you can watch: it clones the environment's repository and runs its setup script in a terminal window. For a project with a long setup this is the longest part of a start, which is what a [saved setup](/docs/environments#saved-setup) removes.

## The network

A desktop has no public address. It reaches the internet through an outbound gateway, so it can clone repositories, install packages and open web pages, and nothing on the internet can connect to it. It cannot reach another desktop. [Security](/docs/security) has the rest.
