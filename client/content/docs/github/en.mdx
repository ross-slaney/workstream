## Sign in with GitHub

You can sign in to Workstream with your GitHub account instead of a code sent by email. If the address on your GitHub account is one you have already signed in with, you are the same person in Workstream, with the same teams and tasks.

Signing in with GitHub says who you are. It does not give Workstream or a desktop access to your repositories.

## Giving a desktop access to a repository

Add a `GITHUB_TOKEN` (or `GH_TOKEN`) variable to the environment, holding a GitHub token that can read and write the repository. Every desktop made from that environment uses it for `git` and for `gh`. A fine-grained personal access token limited to the one repository, with read and write access to its contents and pull requests, is enough.

Commits, branches and pull requests from the desktop are in the name of the account the token belongs to. See [Environments](/docs/environments#variables) for how variables are kept.

## How the agent finishes project work

The agent is told to do project work on a branch of its own and to deliver it as a pull request, never on the default branch. On a desktop that has a token (see below), `git` and the GitHub CLI (`gh`) are signed in with it, so `git push` and `gh pr create` work in the terminal for you as they do for the agent.
